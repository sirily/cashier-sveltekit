# Cashier — итоговый отчёт браузерного QA PR #26

## Вердикт

**Не рекомендую принимать ветку без исправлений.** Основной цикл Journal → Sync и локальные расчёты прошли проверку, но обнаружены ошибки навигации редактора и некорректный расчёт корректировки мультивалютного счёта. Успешная валидация ledger не означает исправность всех экранов.

Это завершённый отчёт широкого исследовательского прогона, а не утверждение о проверке буквально каждой кнопки во всех состояниях. Ограничения перечислены отдельно.

## Система и метод

- PWA: https://github.com/sirily/cashier-sveltekit/pull/26 — ревизия подготовленного стенда `477f28c2653fd668dcf67485425057c914614983`.
- Python server: `4bef2b5d3c97e61ae350728cac56129f8594627f`.
- Единственный существующий локальный Compose/Caddy-стенд: `http://127.0.0.1:8080`.
- Синтетическая книга с серверными плагинами. Production не затрагивался.
- Проверки выполнялись через браузер: интерфейс Journal, выбор счетов, Sync, отчёты, OPFS-редактор, настройки и скачивание файлов.
- В первоначальной части применялись Python-обёртки для браузерных действий и дополнительные технические проверки. После замечания владельца продолжение — только браузерными инструментами, без curl и прямых API-запросов к Cashier. Для ненадёжно адресуемых иконок использованы DOM-клики по элементам интерфейса; внутренние функции и запись в БД ими не подменялись.
- Между продолжениями браузерный контекст менялся. В последнем продолжении профиль был пуст: параметры Sync введены через UI, тестовая книга скачана обычным Synchronize. Это не является доказательством потери данных в прежнем профиле.
- Исходники не исправлялись, commits/push/merge/deploy в production не выполнялись.

## Дефекты

### D1. Высокий приоритет: 500 при возврате из Delete Postings и Reorder Postings

**Delete Postings — воспроизведение:**
1. Открыть сохранённую локальную операцию через Journal → Edit.
2. Добавить третью проводку кнопкой добавления.
3. Открыть Delete Postings, выбрать третью проводку.
4. Cancel оставляет три строки; повторный запрос и OK оставляет две.
5. Нажать галочку возврата в редактор.

**Фактически:** вместо Journal Entry показывается `500 Internal Error`. Повторено несколько раз. Само подтверждение удаления в контролируемом сценарии работает; сбой возникает при возврате.

**Reorder Postings — отдельное воспроизведение последнего продолжения:**
1. Journal → новая операция.
2. Выбрать Expenses:Groceries и Assets:Physical:Cash обычными account picker.
3. Открыть Reorder Postings.
4. Не меняя порядок, нажать галочку.

**Фактически:** `500 Internal Error`.

**Ожидается:** возврат в рабочий редактор с сохранённым состоянием проводок. Корневая причина не установлена; по одному экрану 500 не делается вывод об HTTP-ошибке сервера или потере сохранённой записи.

### D2. Высокий приоритет: неверная база корректировки при смене валюты

1. Открыть историю Assets:Physical:Cash. В текущей книге UI показывает `290 GBP` и `66.81 USD`.
2. Открыть Balance Adjustment. Начальное значение — `Ledger Balance 290 GBP`.
3. Заменить валюту GBP на USD.
4. Ввести Current Balance = 70.

**Фактически:** форма показывает `Ledger Balance 290 USD` и `Difference -220.00 USD`. Число исходного GBP-остатка остаётся прежним и только переименовывается в USD.

**Ожидается:** использовать остаток выбранной валюты из книги либо запретить неподдерживаемую смену валюты с понятным объяснением. Нельзя рассчитывать USD-корректировку от GBP-остатка.

Неверную корректировку не сохранял и на сервер не отправлял. Дефект касается финансового результата, а не только подписи.

### D3. Средний приоритет: причины отказов Sync исчезают после навигации

Подтверждено первоначальным прогоном на конфликте cashier_id и неизвестном счёте.

1. Получить отказ записи при Sync.
2. Убедиться, что конкретная причина отображается: например, `Conflict: cashier_id already exists with different transaction content`.
3. Перейти в Journal и обратно в Server Sync, не запуская новый Sync.

**Фактически:** объяснения и результаты стадий исчезают.
**Ожидается:** сохранять объяснения до следующего Sync согласно контракту manual-transaction-writeback.

Отклонённые записи при этом оставались локально; перезапись серверной записи не обнаружена.

### D4. Средний приоритет: неинформативная ошибка авторизации

В первоначальном прогоне неправильный токен после сохранения и повторного открытия настроек приводил к сообщению только `accounts: Error reading accounts!`.

**Ожидается:** явное объяснение проблемы авторизации. После исправления токена обычный Sync восстанавливался.

### D5. Средний приоритет: Reload server data не работает через локальный deployment-маршрут

Нажатие кнопки показывает `Error reloading data!`.

В первоначальном прогоне дополнительная техническая проверка дала HTTP 403 на `/api/reload`; прочитанная конфигурация Caddy ограничивала маршрут loopback, тогда как запрос браузера проходил Docker-маршрут. Это вывод о тестируемом deployment-пути, не доказательство дефекта реализации refresh в FastAPI и не проверка production.

### D6. Низкий приоритет: About/Help не соответствуют текущему workflow

About предлагает удалённый Ledger Import и описывает Ledger CLI/Hledger. Help ведёт к upstream Cashier Book вместо актуального серверного workflow форка. Это вводит пользователя в заблуждение после удаления импорта.

## Исправление прежнего утверждения

В первоначальном отчёте было написано об успешной клавиатурной перестановке Home. Это утверждение недостаточно доказано: взаимодействие клавишами и повторное открытие само по себе не доказывает изменение порядка. В последнем проходе на Reorder Postings последовательность Space → ArrowDown → Space оставила порядок `Expenses:Groceries`, `Assets:Physical:Cash` неизменным.

Поэтому успешную перестановку с клавиатуры не засчитываю. Это не заменяет проверку pointer drag-and-drop; она не выполнена. Неподдерживаемую клавиатурную операцию отдельно не называю финансовым дефектом.

## Что не проверено / не может считаться пройденным

- Полный Asset Allocation: в fixture нет определения распределения; проверен только путь отсутствующей конфигурации/ошибки Reload.
- Реальное pointer drag-and-drop, все варианты split/reorder/delete проводок.
- Одновременные вкладки: доступные браузерные инструменты не дают управляемого независимого второго tab; конкуренция не имитировалась внутренними вызовами.
- Android-установка, OS Share и реальное обновление PWA на новую версию/миграция.
- Аппаратные ошибки хранения, дисковый rollback сервера, повреждение storage, потеря POST response, все варианты parse rollback и миграций.
- Полный автоматизированный unit/e2e/CI-набор не запускался и не засчитывается вместо браузера.
- Не каждая сумма и каждая котировка большой книги независимо пересчитаны.
- Ошибка 500 исследована на уровне воспроизведения UI; точная программная причина ещё не установлена.
