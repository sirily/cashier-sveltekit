# Design

## Context

See `proposal.md` for removal scope. The baseline is `2809fc3a`, which incorporates release `f40fa7ab` and the eight orphan-file deletions from `7dc6bfad`.

The published contracts in `openspec/specs/` apply in full: `transaction-entry` owns offline capture and source-aware editing; `manual-transaction-writeback` owns identity, send/pull/reconcile and retry safety; `ledger-sync` owns snapshot acceptance and credential protection; `ledger-analysis` owns full-book correctness and freshness. This change leaves those contracts unchanged. Its compatibility work and retained-feature checks belong to the implementation plan, so spec generation is skipped.

Preserving the current report inventory, manual capture/local deletion, export and outbound backup is the agreed scope of this cleanup. Server Sync is the supported external accounting-data ingress; local file, pasted-record and backup-restore inputs are retired. Publication establishes the contracts; known implementation gaps remain separately tracked in `openspec/changes/archive/2026-10-30-add-initial-system-specs/design.md`.

Observed seams:

- Voice Entry is a real drawer route feeding the normal editor; its parser has five unit tests.
- Peer connection code is owned by one demo route, with a commented navigation entry.
- WebDAV/cloud backup owns several pages and remote clients. `cloudBackupService.ts` also exports backup naming used by the retained export page. Shared backup filtering protects the API token.
- `/sync` offers Filesystem and Beancount. `sync-fs.synchronize()` is reachable but always returns `false`; its file loader was used only by the now-removed local ledger service. `/opfs/sync` is another, genuinely operational, bidirectional filesystem path. `/opfs/import-ledger` is a separate directory-copy input and is included in import retirement.
- Ledger-cli branches span `sync-queries`, `appService`, parser utilities, enums, and investment analysis. The active asset-detail loader already injects a worker query function into `SecurityAnalyser`; its optional HTTP fallback is not a reason to delete the analysis.
- `createDAL`/FSDAL and selectable storage factories are unused, but `CashierDAL`, OPFSBackend, the StorageBackend interface, and OPFS file-listing helpers have retained consumers. Folder-scanning/handle helpers serve import and filesystem-sync routes until those routes retire. The storage barrel is live and eagerly creates a filesystem singleton; it cannot simply be deleted.
- Five cross-list drag components are compiled from a string in `tests/ui/drag.test.ts`. The same file also tests live `DragReorderList`; ordinary import scans miss the demo's test root.
- Four build dependencies have no consumers: `@floating-ui/dom`, `@rollup/wasm-node`, `autoprefixer`, `vite-plugin-mkcert`. Tailwind v4 configuration is CSS-based; the source JSON manifest is not the generated PWA manifest.

## Goals / Non-Goals

**Goals:** Individually buildable and tested removal commits delivered in a defined sequence; no financial-data reset; a single supported sync path; unchanged local calculations and capture; explicit retirement compatibility; behavior-based verification before every implementation commit.

**Non-Goals:** Server API work; post-sync transaction mutations; account creation/deletion; analytics redesign; CRDT or alternative sync adoption; broad unused-method cleanup; deletion of reports, manually authored scheduled transactions, outbound backup/export, or ordinary settings controls; changes to release/deployment policy.

## Decisions

Each row is one separately tested commit on top of the preceding state; no slice may rely on a later one to fix compilation or behavior. These are not promises of arbitrary cherry-pick/revert independence: slices share menus, settings, and tests. In particular, slice 3 relocates backup filename generation and slice 6 changes its journal extension/removes Ledger enum support, so slice 6 must account for slice 3's helper location (or the old location if applied separately). Rollback must resolve affected dependencies and rerun gate G.

### 2. Compatibility cleanup is narrow and repeatable

Use a fixed list of exclusively retired credential/settings keys, not a database reset. WebDAV credential state (`webdav-settings`) and verified-exclusive cloud tokens are purged locally and filtered from outbound backup. Retire restore/import inputs in slice 4 and remove their exclusive filtering/helpers after the final consumer disappears. Verification covers preserved data and outbound/diagnostic credential protection, not correctness of the retiring restore/import functions. Never contact a retired endpoint to clean it up. Preserve the local `syncApiToken`, server URL/root/selection details, journal, selected book, scheduled records, and unrelated preferences.

Map recognized `filesystem`/`ledger` source choices to the sole supported server flow without fabricating a URL or token. A previously loaded, unconfigured client with required local references remains able to save offline; Sync asks for valid configuration. After slice 4 older backup files and pasted settings have no supported ingestion path. Handle existing settings normalization at the retained settings-load boundary with tests, not scattered report fallbacks. Decode legacy strings even after removing their enum values. Preserve server-selection settings such as `syncServers` and `syncActiveServerId`, which have live server consumers despite their placement under a peer-related comment.

Remove retired menu actions and routes together. Old URLs use the normal safe not-found view or a non-mutating redirect; they cannot initialize the retired microphone, peer, remote-backup, file-import, restore or filesystem-write code. Retained journal, Sync, export and backup actions remain reachable.

A code revert does not restore intentionally erased legacy credentials; rollback notes must state that owners would need to re-enter them if the retired feature were reintroduced. No financial data migration is needed.

Alternative rejected: ignoring old settings or retaining dormant clients as a fallback. That either strands installations or quietly reintroduces a second sync path.

### 3. Preserve bookkeeping, not misleading names

`PtaSystems.ledger` currently also supplies the journal export extension in shared filename generation. Removing that enum value must not accidentally remove journal export. Retain readable Beancount output and choose its `.bean` filename explicitly in slice 6; add a content/download check rather than testing an internal enum.

The authoritative server remains Python Beancount. Local `rustledger.ts`, `ledgerService`, `ledgerWorkerClient`, worker and cache are retained. Do not remove them due to misleading deprecated headers or the word Ledger in an identifier. No new edit/delete/account API is inferred from this change.

External accounting data enters through the server Sync flow. Retire file/directory import, pasted transaction parsing, OPFS upload and file-drop, settings/scheduled backup restore, and arbitrary bulk JSON settings writes. Manual transaction/schedule entry and ordinary settings controls remain local authoring. Test fixture code may seed OPFS/IndexedDB directly; fixture setup is not a reason to retain a production importer.

Keep existing journal/book/reference/scheduled data on upgrade. Preserve OPFS browsing and selection used by retained analysis/settings. `importManifest` still serves OpfsFilePicker's imported-file modification marker: retain that dependency or remove the obsolete marker atomically before deleting its helper. `concurrency.ts` has investment-analysis consumers. Local storage APIs remain available to the journal and server pull; the supported-ingress boundary is not a ban on local writes.

Asset allocation still reads an existing selected TOML in OPFS, but its dedicated server-sync branch currently rejects definition import and ordinary book pull does not establish delivery of that file. Record this delivery gap for separately scoped server/client work. Preserve existing allocation data, selector, parser and analysis; do not invent a new API or keep a hidden importer as a workaround.

Export preserves journal content and synchronization identity. Outbound local backup serializes ordinary settings and scheduled records with credentials filtered out. Verify actual copy/download/share content and unchanged local data. Remove restore controls and source-reading state; verify old restore URLs and file/paste/drop attempts cannot mutate the journal, book, settings, schedules or active token. Server book recovery uses Sync.

### 4. Shared regression gate runs before every runtime commit

Run baseline checks before changing runtime code. The previous audit observed a formatter failure in `.serena/project.yml`; diagnose its current state instead of assuming it is fixed. The current container also has no `/home/node/.cache/ms-playwright` directory. Check the configured browser executable/cache and OS dependencies before declaring E2E runnable; installing the required test tooling is setup, not permission to skip tests. Report installation/network failures and stop.

Run the static/build commands below and all retained-workflow unit/browser checks before **each** implementation commit. Select the test scope at the start of implementation: exclude tests dedicated solely to retiring functions, and split mixed tests so retained assertions remain exercised. Record the selected test files/name filters and their rationale. The unfiltered runner commands below are used once that suite selection is reflected in the invocation or test configuration; they are not a requirement to exercise retiring functions.

```sh
npm run check:specs
npm run lint
npm run lint:svelte
npm run check
npm run test:unit -- --run
npm run check:build
npm run test:e2e -- --workers=2
```

Playwright's existing `webServer` owns its bounded build/preview lifecycle on port 4173; do not start or replace the owner's port-5173 dev server. Rebuild changed assets before browser verification. The browser gate covers retained navigation, journal, server Sync, accounts/history/reports, export/backup, PWA lifecycle and production packaging. Include only the live-reorder case from the mixed drag test and the credential/export cases retained from mixed backup tests. Correct operation of deleted/proposed-for-deletion functions is outside this gate.

New shared scenarios cover retained functions and the safety of removal. Local editor identity loss (archive G1) is tracked separately in `openspec/changes/preserve-local-transaction-identity/`; its fix and regression belong to their own commit. Keep the published local-edit/identity guarantees when checking retained capture and writeback.

Do not verify or repair the functional correctness of code selected for deletion. In particular, restore's clear-before-insert token-loss bug (archive G12) does not block cleanup and is not assigned a fix or failure-path test. The same rule applies to retiring import, voice, peer, filesystem and Ledger-cli paths even before their removal slice. Exclude tests dedicated solely to those functions from the required cleanup gate; separate any shared retained-behavior assertions instead of disabling them. Static/build checks still cover code that remains in each intermediate tree. Verify the effects of removal: existing journal/book/settings/schedules/token survive, outbound exports remain credential-free, and retired entry points cannot mutate data or initialize removed integrations.

The browser sync suite uses mocked HTTP. Its pass is not proof against the real Python server. Report real-server integration as separately passed/not run, with a disposable book and explicit credentials if that environment is provided; never send tests to the owner's real book. No real-server credentials/environment have been provided, so this is not silently required or silently counted as passed.

### 5. Review and graph gates are per commit

Before each edit, run targeted impact and verify direct consumers using Serena/current source, including Svelte routes, string-built test imports and shared credential helpers. UNKNOWN is unresolved; HIGH/CRITICAL needs an explicit warning and investigation.

The current MCP index is stale. Before graph-dependent runtime edits, refresh with the project runner and verify that the index represents current relevant source, including relationship-affecting dirty changes; unresolved staleness or a failed refresh blocks those edits and commits, not merely a warning in the handoff. Before each commit, inspect only the intended staged slice, run `detect_changes` against verified-current evidence, account for affected paths, and reject partial/truncated graph results. Do not use an empty graph result as proof of safety. Run a focused regression review after the slice and after fixes. Commit only when required behavioral/static checks and review pass; a later edit invalidates earlier evidence relevant to it.

### 6. Documentation is a separate preparation change

`docs/architecture.md`, README and AGENTS explain current server authority, real OPFS overlay, worker/local-edit separation, confirmation identity and credential boundaries. Delete the requested historical `docs/completed-projects/` after extracting surviving facts and fixing links; do not copy old plans into new requirements.

The four published specifications and their archived originating change remain unchanged. Runtime slices update affected implementation documentation and tasks; architecture documentation describes the system's structure and data flows.

## Risks / Trade-offs

- Shared settings/backup code can leak or erase the active token → narrow retired-key cleanup, outbound-export filtering and unchanged-state checks for retired restore inputs; retiring restore correctness is outside the cleanup test gate.
- Old source settings can leave installations on an unreachable workflow → explicit legacy-source compatibility without network side effects.
- Local-only or stale analysis can look like a valid empty book → retain worker availability/freshness/completeness behavior and report tests.
- Deleting a storage barrel or shared database can break server pull/local editing → verify retained OPFS consumers and preserve stored data; remove import-exclusive helpers only after their last caller retires.
- Removing test-only code can break a shared compiler harness → split demo coverage without deleting live reorder tests or esbuild-wasm.
- Full gates are slower than a final-only test run → accepted cost of individually verified commits with dependency-aware rollback.
- Old history can claim functionality the fork never implemented → current source/OpenSpec outrank removed upstream project notes.
